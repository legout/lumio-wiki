# Release notes — v0.1.1

Lumio v0.1.1 publishes the three inter-member distributions
([ADR-0010](../adr/0010-uv-workspace-and-progressive-packaging.md)) as
installable wheels from PyPI:

| Distribution | Installs | Use when |
|---|---|---|
| `lumio-wiki` | `msgspec[yaml]`, `msgpack`, the `lumio-wiki` CLI, and the packaged Agent Skill | Portable, model-free Knowledge Base from any coding agent. |
| `lumio-lancedb` | `lumio-wiki` + LanceDB + PyArrow | BM25 / vector / semantic / hybrid retrieval. |
| `lumio` | `lumio-wiki` + `lumio-lancedb` + the full Stario web app, providers, storage, auth | The deployable chat application. |

The three wheels release as one **lockstep family** (see
[packaging](../packaging.md) "Releases"): every member carries the same
version, built from one tagged commit.

## Migration from a repository checkout

Nothing changes for the development workspace: `uv sync` continues to
install the three members editable from the checkout, and the workspace
lockfile remains the only lockfile.

For consumers, editable/checkout installs are no longer required:

```bash
pip install lumio-wiki              # was: pip install -e packages/lumio-wiki
pip install 'lumio-wiki[s3]'        # + S3/MinIO Knowledge Base Locations
pip install lumio-lancedb           # + the enhanced retrieval adapter
pip install lumio                   # + the full deployable web application
```

Migration notes:

- **`lumio.core` re-exports are temporary.** Canonical Knowledge Base
  behavior lives under `lumio_wiki`; the `lumio.core` / `lumio.core.<module>`
  import paths are pre-1.0 compatibility re-exports and will be removed
  before 1.0. Migrate imports when adopting the wheels.
- **Inter-member version bounds are enforced at install time.** The
  `lumio` and `lumio-lancedb` wheels bound their `lumio-wiki` dependency to
  the released `0.1` family (`>=0.1.1,<0.2.0`). A family-crossing partial
  upgrade (for example `lumio==0.2.0` with `lumio-wiki==0.1.1`) fails in
  `pip`/`uv` resolution with a conflict naming both bounded ranges, not at
  runtime. The family always releases together — upgrade all three
  together.
- **The packaged Agent Skill ships inside the wheel.** `lumio-wiki skill`
  locates, installs, and updates it; coding agents no longer need a
  checkout to resolve the skill (`lumio-wiki skill path`).

## Optional extras

Extras keep the base wheels lightweight ([ADR-0010](../adr/0010-uv-workspace-and-progressive-packaging.md));
each capability is opt-in and fails with actionable guidance naming the
exact install command when invoked without it:

| Extra | Brings | Capability |
|---|---|---|
| `lumio-wiki[documents]` | LiteParse, MarkItDown, AnyDoc | PDF / scanned-PDF / image / office / HTML ingestion. |
| `lumio-wiki[llm]` | `openai` | Unattended OpenAI-compatible Distiller. |
| `lumio-wiki[s3]` | `obstore` | S3/MinIO Knowledge Base Locations. |
| `lumio-wiki[all]` | documents + llm | Document conversion and unattended distillation together (still LanceDB-free). |
| `lumio-lancedb[embeddings]` | `sentence-transformers` | Local embeddings for the adapter. |
| `lumio-lancedb[s3]` | `obstore` | Remote (S3) index support. |
| `lumio[s3]` | `lumio-wiki[s3]` | S3 Locations for the full app. |
| `lumio[semantic]` | `sentence-transformers` | Local embeddings for the app's LanceDB backend. |

Torch never enters `lumio-wiki` or the base `lumio-lancedb` adapter; LanceDB
never enters `lumio-wiki`; the web application stack never enters either.

## Supported Python version

All three wheels require **Python ≥ 3.14**. The deployment journey, the
packaged Agent Skill, and the retrieval backends are certified on 3.14
only; earlier interpreters are not supported in this release family.

## Known MVP limits

- **Single-tenant.** One deployable app instance serves one Owner and its
  Readers; there is no multi-tenant hosting (see the
  [platform PRD](../prd/0001-knowledge-agent-platform.md)).
- **Pre-1.0 API churn.** Per the pre-1.0 policy, breaking changes may land
  in any `0.MINOR` release; pin the family when that matters to you.
- **S3 Published Versions are immutable reader Snapshots.** Authoring is
  local (or via proposal capture); an S3 location is never a writable
  filesystem. Artifact retention (Source Artifacts) is opt-in per
  publication.
- **Remote LanceDB indexes are disposable projections.** Markdown/YAML
  Compiled Pages remain canonical; a missing derived index falls back to
  zero-index lexical retrieval rather than failing.
- **Publication of this release itself is human-gated.** Wheels are built,
  attested, and verified by the release workflow, but promotion to PyPI
  requires repository-owner approval (see
  [packaging](../packaging.md) "Releases").
